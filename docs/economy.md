# Экономика CaseArena («хитрый способ конторы быть в плюсе»)

Принцип: **платформа структурально прибыльна без обмана игроков**. Все проценты,
показанные пользователю, — реальные. Прибыль возникает из математики механик.

## 1. Кейсы: RTP < 100%

У каждого кейса есть целевой `rtp` (return to player). Seed-солвер
(`solveCaseWeights`) подбирает вес самого дешёвого предмета так, чтобы фактический
EV выпадения точно равнялся `price × rtp`:

```
EV = Σ(weight_i × value_i) / Σweight_i = price × RTP
```

| Кейс | Цена | RTP | Маржа конторы |
|---|---|---|---|
| Starter Crate | 100 | 88% | 12% |
| Copper League | 250 | 87% | 13% |
| Neon Reef | 400 | 88% | 12% |
| Crimson Vault | 750 | 93% | 7% |
| Royal Court | 1200 | 90% | 10% |
| Ghost Protocol | 1500 | 89% | 11% |
| Void Rafale | 2500 | 91% | 9% |
| Mythic Abyss | 3500 | 92% | 8% |

Игрок видит точные шансы на странице кейса (эндпоинт `/cases/:slug/odds`).

## 2. Апгрейд: комиссия 5%

```
chance = (inputCost / targetValue) × 0.95, клампится в [1%, 92%]
требование: targetValue ≥ 1.2 × inputCost
```

EV игрока = `chance × target − input = −5% × input`. Пример: 1000 AP → цель 5000 AP:
честный шанс 20% → с комиссией 19% → EV = 950 AP.

## 3. Контракты: EV выдачи = 81%

Из каталога берётся пул исходов в диапазоне `[0.25×S, 6×S]`, где S — сумма входа.
Веса исходов `∝ v^(−α)`; экспонента α подбирается бинарным поиском так, чтобы
`EV = 0.81 × S` (функция `contractDistribution`). Пул и честные шансы видны игроку
в превью (`/contracts/preview`).

## 4. Продажа: 30% выкупа

Система выкупает предмет за `floor(value × 0.30)` — долгосрочное поглощение AP
(синк). Плюс «хламовые» предметы (25–65 AP) в дешёвых кейсах дают реалистичную
кривую редкости и удерживают RTP даже для кейса за 100 AP.

## 5. Откуда берутся AP (эмитент — только система)

| Источник | Сумма |
|---|---|
| Приветственный бонус | 2500 AP |
| Ежедневный бонус | 100–250 AP / предмет |
| Админ-коррекция | вручную (аудируется) |

Ни одна механика не позволяет купить AP за реальные деньги и не позволяет
конвертировать предметы обратно в деньги. AP-поток строго односторонний:
система эмитирует → игроки тратят → контора аккумулирует.

## 6. Учёт и контроль

- Каждое движение — строка в `Ledger` (immutable, `balanceAfter`).
- Админ-дашборд: сожжённые/выданные AP за 14 дней, нетто-прибыль, разбивка по типам.
- Юнит-тесты `economy.spec.ts` фиксируют: точный EV кейса, отрицательный EV апгрейда
  на всей сетке входов, точность 81% контрактов, границы XP.

## 7. Пример потока

```
Игрок: +2500 (welcome) → открывает 20 кейсов по 100 (−2000, контора +240)
       → продаёт хлам (+150) → 2 апгрейда по 500 (−1000 оборота, контора +50)
Итог: у игрока предметы на ~350 AP ценности, у конторы — +290 AP нетто.
```
