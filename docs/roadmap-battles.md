# Бои (Case Battles) — РЕАЛИЗОВАНО в v2

> Актуальная документация: `docs/battles.md`. Ниже — исходный план (выполнен).

## Что заложено

- Все игровые результаты идут через авторитетный серверный пайплайн с CSPRNG и
  аудитом (seed+roll) — бои переиспользуют его без изменений.
- `CaseOpen` уже хранит всё нужное для «раунда боя» (кейс, предмет, время).
- Envelope API и guard-система допускают WebSocket-слой без ломки REST.

## План внедрения

1. **Battle Engine (NestJS-модуль `battles/`)**
   - Состояния: `WAITING → READY → STARTING → ROUND_RUNNING → ROUND_FINISHED → COMPLETED | CANCELLED`
   - Сущности: `Battle`, `BattleParticipant`, `BattleRound`, `BattleReward`
   - Раунд: каждому участнику — результат открытия того же кейса (тот же `CasesService.open`
     внутренний вызов), сумма ценностей определяет победителя, победитель забирает
     все выпавшие предметы (перевод статусов `OWNED` между инвентарями — транзакцией).
2. **Realtime**: Socket.IO namespace `/realtime`, комнаты `battle:{id}`, события
   `battle:created/joined/starting/round_started/reward/round_finished/completed`.
   Сервер — единственный источник истины.
3. **Без денег**: участие стоит Arena Points (списание через `BalanceService`),
   выигрыш — только предметы. Никаких ставок/выплат.
4. **UX**: лобби `/battles`, создание (2/4 игрока, 1–10 раундов, приватные с инвайт-кодом),
   экран боя с слотами игроков и анимированным скорбордом.
5. **Античит**: нельзя присоединиться после старта; нельзя провести бой дважды;
   идемпотентность наград через `BattleReward` unique-констрейнт.

## Оценка

Backend-модуль + сокеты: ~2–3 дня; лобби и экран боя: ~2 дня; тесты жизненного
цикла боя: ~1 день.
